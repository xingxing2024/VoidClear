# 六轮性能与故障核查改进（已验收）

目标：减少 MySQL 全箱读写及重复解码，提升异常交付的可核查性，补 Folia/MySQL 实服组合。不能把新增测试当成断电原子保证。

## 本轮范围

- 异常交付证据：仅失败时写入 `delivery-failures/*.properties`，含玩家、页码、已接受状态、失败阶段、操作前与计划后的背包/光标/副手/页面/掉落物字节。写入后 force；磁盘失败会显式报错，不影响锁定菜单。
- 快照是核账证据，不是领取凭证；失败阶段自身可能部分生效，禁止自动回放或按快照直接补发。正常路径只保留内存副本，不同步写盘；文件仅故障时生成，管理员核查后自行归档。
- 文件含玩家 UUID 和完整物品元数据，应按玩家数据限制目录权限，不公开分享。没有自动清理，避免删除未处理的故障证据。
- 平台脚本新增 Folia/MySQL，隔离目录 `target/platform-tests/folia-mysql`、端口 25656，复用隔离测试数据库，不涉及正式数据。
- MySQL 差量写已实施：只删除移除 ID，只插入新 ID，只更新内容或位置变化的记录，检查批次影响行数；仍在同一个元数据锁事务内递增 revision、提交后交付。
- 复核后不采用 revision 相等就跳过事务内全表读的计划：继续读取最新 rows 作为差量基线，避免额外依赖外部数据绝不漂移的假设。没有改动 SQLite 保存/rebase 协议。
- 解码缓存按 ID 和字节身份/内容双重校验，缓存对象只读，合并前 clone；至多 10000 项、8 MiB 序列化负载，跳过大于 8 KiB 的 NBT 项。此限制不代表解码后堆内存上限，需要生产堆观测。

## 当前边界

本轮的交付文件是在异常被捕获后写入的，不是提交前持久化 WAL。突然断电/进程被杀时可能没有文件；即使有文件也不能证明世界或玩家最终存档状态。不提供 exactly-once、自动补发或断电无损承诺。

MySQL 仍在调用线程同步获取事务锁和全表读；差量写与解码缓存减少工作量，没有采用 revision 相等复用，也不等于异步预留架构，不能消除远端数据库超时造成的阻塞。JDBC 批次返回 `SUCCESS_NO_INFO`（例如打开 `rewriteBatchedStatements`）时不能精确核验逐行影响数；默认测试 URL 未开启该选项。

旧包 reviewed5 与数据未覆盖；修改前备份 SHA256 `89257D639E51FB3B4703DF13F88B31EA5B3F670C67E51892FB735703E6C064B0`。
