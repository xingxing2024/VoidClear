# 四轮评估处理记录

## 本轮修改

- MySQL watcher：revision 不变时结束只读事务，跳过全表读取、字节克隆及计数缓存失效。新增隔离 MySQL 断言，检查无变化保留缓存、有远端变化刷新数据。
- 清扫拒收收尾：逐个结算没有回调的区块份额，移除测试中手动调用 settle 的补救，让测试验证真实产品路径自行完成。
- 清扫 daily 配置：timer 与 trash.clear 共用时刻校验，非法 mode、空 daily 列表和非法时刻拒绝加载，新增对应自检。
- CI：Windows runner 在线构建并准备依赖后执行 check.ps1，开启断言；不是只执行空的 mvn test。尚未在 GitHub runner 实跑。
- history：移除不存在的操作类型与玩家筛选补全提示，保留旧日志筛选兼容性；README 明确目前仅记录 SWEEP 汇总，不是玩家存取审计。

本轮交付另存 `target/VoidClear-3.0.0-reviewed4.jar`。旧 reviewed2 JAR 不覆盖。

## 未在本轮重写的内容

- MySQL 同步全箱事务、增量计数、堆叠索引、批量存入：仍是已知性能限制。慢事务持有共享存储锁时，不仅影响调用玩家，还可能阻塞区域/主线程及其他等待同一锁的查询。不能将本地满箱快照直接当成最新数据库事实。
- 旧 trash.yml 迁移：报告指出的半迁移风险仍待独立修复与故障注入验证。不要手动重复导入，也不要自动清空非空目标数据库；需要完整备份后处理。
- 坏物品字节启动时反序列化、架构抽象清理、最低 API 版本实服覆盖、交付目录整理尚未在本轮修改。

未覆盖 Folia + MySQL 组合、断电与生产负载。没有部署正式服。
