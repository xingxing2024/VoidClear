## 发现

### 1. 当前没有检出直接复制的具体实现

- 当前两项目间没有完全相同的受检文本文件。
- 去掉注释、包声明及导入后，达到 25 token 的精确匹配只有 Bukkit 标准补全方法签名及边界：`onTabComplete(CommandSender sender, Command command, String alias, String[] args)`，不能据此认定复制业务逻辑。
- 标识符和字符串抽象后的比较，没有检出达到 90 token 的连续相同结构。这种比较只能辅助发现疑点，不能排除拆分、重排或短片段复用。
- 对上游历史的比较，没有整文件相等或达到 40 token 的连续匹配。
- Java 中长度至少 10 的共同字符串为通用文件名/API/命名空间，如 `messages.yml`、`config.yml`、`getOnlinePlayers`、`minecraft:`，未发现有辨识度的原项目长文案复用。
- 去空白后长度至少 16 字符、含中文的整行比较没有匹配；不覆盖改写、跨行拼接和较短文字。

### 2. 功能和配置语义确有参考关系

原项目 `src/main/resources/config.yml` 中的名单、命名实体策略、每世界规则、`id/name/lore` 物品豁免、以 `*` 开头的模糊匹配，与 VoidClear 提供的能力存在明显对应。默认清扫周期 3600 秒、批量值 600、提醒 60/30/15/5 秒、垃圾箱周期 7200 秒和提醒 30/10/5 秒也相同。

这些对应证明设计继承/参考值得公开说明，但通用功能、配置数值或实现需求相似不自动等于复制了受保护的具体表达。项目之间已有参考接触，也不能把本次审查称为隔离条件下的独立开发证明。

### 3. 核心实现存在实质区别

| 范围 | ClearEntity | 当前 VoidClear |
